# 0.25 独立レビュー

2026年11月7日。独立レビュー担当は Sol 6.1。保存・採点・状態遷移の実装担当とは別の担当が、仕様と旧実装を読み、独自の境界検証を作成して確認した。Astra は使用していない。

最終の独立自動検証は **604項目成功、0項目失敗**。実装中に再現した保存失敗・フォーカス喪失の不具合は、修正後に同じ操作を再実行して解消を確認した。

## 検証方法と範囲

専用の空の保存先と `SLT_TEST_DATA=1` を使い、ゲーム操作、ファイル保存、実際の非同期保存処理、武器別採点を別プロセスで検証した。実ユーザーの保存データは開かず、変更していない。初期化試験で操作したのは検証用に作ったデータだけである。

| 系統 | 成功数 | 主な確認内容 |
| --- | ---: | --- |
| ゲーム操作・配点曲線 | 550 | 誘導の外れと有効命中、通常成績との分離、一度だけの進行、4撃破後に累計5、Tab・Esc・フォーカス喪失、記録分割、旧難易度、不正な前回武器、再起動時の復元 |
| 保存と初期化 | 17 | 一時書込・直前保存・確定時の失敗、原状態の保持、全データと設定の初期化、初期化前の退避、新世代だけの復旧、旧バックアップと旧版データの自動復元防止 |
| 実際の保存中操作 | 14 | 保存中のTab解放、編集確定中のフォーカス喪失、測定切替失敗、編集保存失敗の表示、初期化と実行中の保存処理の競合 |
| 武器別採点・加点表示 | 23 | 5種目の表示額と実額、表示時間、中心報酬の合計倍率、速度・連続加算の維持、武器別プレビュー単位 |

ゲーム操作の検証は、Windows版Godot 4.7.2の実描画プロセスを関数から自動駆動した。保存だけの試験は画面なしで実行した。これは**自動操作の検証であり、人間による手動操作の記録ではない**。画面サイズごとの視認性、指の見え方、実際の入力操作と配布版の確認は、主担当の検証資料を参照する。

## 再現後に修正を確認した点

- 編集確定の保存中にフォーカスを失うと、保存完了後に練習へ勝手に戻る状態を修正。完了後も一時停止を維持する。
- 測定中の武器変更保存に失敗した際、元の測定収集処理だけが終了済みになる状態を修正。変更前の測定を保持し、再試行または安全な再開ができる。
- Tab内の変更保存失敗が、隠れたEscパネルにだけ表示される状態を修正。Tabを押している場合は操作中のパネルへ表示する。
- 標的編集の保存失敗時も、Tab解放後は説明付きの一時停止へ移す。編集画面が押下外で操作可能なまま残らない。
- 保存中のTab解放を記録し、保存が終わった時点で適切に閉じる。射撃アクション・バースト・測定射撃の入力を残さない。
- 左側半分で端の報酬が変化しない曲線を修正。全域で右ほど端が下がり、中心が上がる。
- 武器別プレビューを実際の基礎点・武器補正へ合わせる。アサルトは有効追従1秒、バーストは命中1発を単位とし、撃破加点は別途であることを説明する。
- 不正な前回武器を整数へ丸めて選択しない。小数、文字列、範囲外はハンドガンへ戻す。
- 非訓練画面の武器選択への迂回経路、Escの旧難易度変更への入口、5達成後の常時一覧表示を除去。新しい自由練習へ旧難易度の倍率・標的条件を持ち込まない。

## 採点の実数照合

初期編集値は `0.5`、自由練習の採点版は `5`。実際に中心へ命中させたときの合計を、同じ射撃事実を旧版の式へ入れた合計と比較した。端数表示前の値で比較している。

| 種目 | 旧合計に対する新合計 |
| --- | ---: |
| ハンドガン | 約2.000倍 |
| アサルト | 約2.073倍 |
| バースト（3発撃破加点を含む） | 約2.100倍 |
| グリッド | 約2.100倍 |

同じ試験で速度・連続成功の加算額は旧式と一致した。中心分が旧中心上限へ切り詰められないことを確認した。測定は旧固定式と一致し、グレネードは従来の一発7〜9クレジットの範囲を維持した。

5種目すべてで、短い連続加点の表示合計が採点の増分と一致した。表示残存値は旧 `0.9秒` に対して `1.8秒`、集約用の時間値は旧 `0.7秒` に対して `1.4秒`。表示処理からのクレジット付与は行わない。

## 確認できた保存上の境界

初期化では、実行中の旧保存を完了させてから保存処理とキャッシュを交換する。古い保存要求が残った状態から初期化し、さらに新しい保存を行っても、旧クレジット・進行・感度が復活しないことを実行確認した。

初期化後の主保存を失わせた場合は新世代の直前保存だけを復元する。意図的に旧世代の直前保存へ差し替えた場合と、旧版保存だけを残した場合は、復元失敗の説明を返し、古い進行や設定を再移行しなかった。初期化前の退避データが別の退避先へ残ることも照合した。

## 凍結前の利用権差分

604項目の独立検証後、旧プレイヤーの測定利用権について追加差分を読取レビューした。履歴内に空でない測定データがあれば、中断した測定だけの場合も利用権を維持する。仕様の「既存の測定履歴がある人」に合わせた互換処理であり、兵士への採用可否、測定完了回数、防具解放、クレジットの計算条件は変更しない。

中断履歴の回帰ケースを含む `progression_tests.gd` を、独立担当も専用保存先で再実行して成功を確認した。この追加実行は上記604項目の件数には含めていない。

## 検証の限界

- 保存先の実際の空き容量不足、電源断、OS強制終了は実行していない。書込・直前保存・確定失敗は注入した失敗で確認した。
- 配点曲線の501点以上の数値確認と武器別照合は、実プレイヤーの分布を測ったバランス評価ではない。
- 複数種目を高速に生成・破棄する武器試験の終了時、Godotの描画終了処理がテクスチャ4件、計約1.33MiBの解放診断を出した。スクリプトエラー、採点不一致、保存破損は発生していない。通常起動・通常終了時の確認とは区別する。
- この独立検証はソース状態に対する結果であり、公開ZIPのダウンロード・署名・更新適用の検証を代替しない。
