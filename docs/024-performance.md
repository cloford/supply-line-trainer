# 0.24 起動・Esc応答の計測と検証

公開済み0.23のPCKと0.24の同じシーンへ、既存の `performance_023_tests.gd` / `profile_game_023.gd` を適用した。Windows / Godot 4.7.2、隔離APPDATA、`SLT_TEST_DATA=1`。履歴・測定・採用はすべて生成fixtureで、ユーザー保存は使用していない。各条件一回の実測値であり、機種・負荷による変動を含む。生の内訳は [024-performance.json](024-performance.json) に保存した。

## Escハンドラーの所要時間

単位はミリ秒。保存中はwriterを先に起動してからEscを実行した。

| 保存データ | writer | 公開0.23 | 0.24 |
|---|---|---:|---:|
| 新規（履歴0件） | 待機中 | 10.577 | 0.300 |
| 新規（履歴0件） | 保存中 | 7.975 | 0.284 |
| 合成ペイロード100件 | 待機中 | 1874.853 | 0.394 |
| 合成ペイロード100件 | 保存中 | 3877.816 | 0.324 |
| 有効測定100件＋採用6件 | 待機中 | 15418.138 | 0.505 |
| 有効測定100件＋採用6件 | 保存中 | 32047.665 | 0.388 |

0.23はEscのcheckpoint要求に続き、PAUSED後の保存でworkerをjoinし、さらに同期保存していた。有効測定100件では保存待ちが約15秒、writerが動いていれば約32秒となり、メニューの描画へ戻れなかった。`menu_visible=true` はハンドラーが返った後の状態であり、その待ち時間中に描画できたことを意味しない。

0.24は最初に訓練モード・発砲・バースト・測定入力を停止し、メニューを表示する。成果の台帳更新はメモリ上で行い、保存は要求番号を増やすだけ。PAUSED中も次のフレームで保存を開始し、メニュー描画と操作を継続する。保存要求を保存済みとは扱わず、失敗した要求はdirtyのまま最新snapshotで再試行する。

## 内訳と残る費用

JSONの `checkpoint_us` はメモリ台帳、`save_current_us` は保存境界、`pause_post_frame_us` は次フレームの処理、`snapshot_us` は直近dispatchの小snapshot作成時間である。`pause_menu_ui_us` はcheckpoint以外の残差で、0.23では同期保存とjoinを含む。内訳には親子の重複があるため単純加算しない。`frame_wait_us` はheadlessのフレーム待ちで、GPU描画時間ではない。

SceneTree自体はpauseせず、`mode=PAUSED(5)`、`paused=false`、`time_scale=1`、focusありを維持する。headlessのmouse値0は描画環境の制限を含むため、実ウィンドウのフォーカス・Esc操作は別途確認する。

全履歴のworker専有deep cacheは初期設定時に作る。この費用は残しており、有効測定100件のfixtureでは約0.9秒だった。Escと通常再開では再構築しない。JSON化・検証・ファイル更新も大履歴では依然として約15秒かかるが、単一worker側で行う。

終了・更新・購入・採用・設定適用・条件変更など確定が必要な操作は、処理中画面を出してフレームを返しながら同じwriterの完了を待つ。購入候補や条件候補は成功後だけライブ状態へ採用する。確定候補は小snapshot、旧private cacheへの参照plan、新規・差替recordのdeep copyだけを渡す。ライブDictionaryをworkerと共有せず、同じファイルへの並行writerも作らない。正常な訓練終了時は確定した同内容を二重保存せず終了する。

## 通常起動の描画確認

`update_display_tests.gd --boot-flow` の通常 `is_test_mode=false` 経路をGPUで実行し、手動で時計を進めずに確認した。1280×720、1920×1080、1024×768の各起動で、描画された全フレームに準備画面がなく、静止標的と照準、起動pop一回、自動iris→3→2→1→訓練の順序を確認した。irisは約0.83〜0.89秒、各数字は最終PCKで約0.98〜1.15秒（PNG保存等の負荷を含む）。演出中の訓練時間・発射・成果は0、カメラ・標的・FOVは不変。GPU計測ではOSの起動時フォーカス移動による自動pauseを分離するためfocus_exitedだけを切り離している。OSの実フォーカス操作は未確認。内部通知の検査と分けて扱う。

同一配布EXEと未変更製品PCKを使用する検証用起動ラッパーでも、新規・重い有効測定100件の保存／再起動を確認した。重い条件のEsc入力投入からメニューを含む実GPU描画は33.113ms、終了保存21.973秒の間に1,245フレームを描画した。[方式・制約・画像](024-verification.md)、[実EXEの照合結果](024-release-exe.json)。OS物理入力や人の試遊とは異なる。
