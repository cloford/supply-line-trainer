# Aim Runner 0.2.7のWindows検証

| 再現条件 | 原因と修正 |
| --- | --- |
| 感度を1から2に手入力、またはスライダーのみ変更 | 入力欄とスライダーで更新経路が分かれ、上限も100と10に分かれていた。相互反映と換算・編集状態の更新を揃え、0.001〜100を扱う。 |
| 設定の入力欄からTab、Shift+Tab | 射撃場用の処理が画面判定より先にTabを消費していた。射撃場の武器トレイを開閉する場合に限定し、フォームでは表示中のダイアログを移動範囲にする。 |
| ターゲット編集の最小高 | 端の参考値のベースラインが最小高142の下端と一致した。文字の高さをLabelとContainerに任せ、中心・端の参考値を配置する。 |
| 日本語名を入力し、保存ボタンを押したまま部隊を更新 | 入力欄のフォーカス喪失後、戦況更新が保存済み名を再代入した。選択枠ごとに入力欄を初期化し、保存処理は押した時点の枠を使う。 |
| 1024×768で60秒測定の結果を表示 | 結果カードの幅1100が表示領域を超えた。モーダルの幅を表示領域から左右の余白を引いた値で制限する。 |

WindowsのRTX 4060で1280×720、1024×768、1920×1080を描画した。起動案内、射撃HUD、Tab、各設定カテゴリ、編集、メイン、部隊、記録200件、60秒測定結果を自動確認した。画面切替とウィンドウサイズ変更に加え、Godotへ渡す入力イベントでスライダー両端と部隊名の保存ボタンを操作した。Windowsの表示倍率125%・150%、OSポインター経由の操作、人による試遊は未確認。

0.2.6の配布EXEを隔離し、テスト用PCKから公開版のデータを読み込む方法で、自動更新の適用と再起動を確認した。0.2.7のEXE・PCKへの差し替えと旧ファイルの退避をハッシュで照合し、クレジット、感度12.3456789、日本語の部隊名、案内既読が保持された。

公開後は、自動適用を有効にした0.2.6から正式ZIPを取得した。検証後にメイン画面へ戻ると更新ボタンを押さずに0.2.7へ再起動した。ファイル照合とセーブ保持も再確認した。正式APIを照会した0.2.7の配布PCKで、メイン画面と更新設定に最新公開版との一致と確認時刻が表示された。

Windows ZIPのSHA-256は `3bdf63f642a127d488dd49af51b8fa27dfca1da0dfaac50d49bd2f83e8e0386b`。
