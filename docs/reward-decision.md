# 報酬分析と配点維持の判断

## 今回の到達点

改善案3は再現・分析・検証手段の整備まで。配点調整は採用していない。武器係数0.105 / 0.05 / 0.075、その他上限20%、scoring_version=4を維持する。metrics_version=1／training_rules_version=1も維持し、技能比較を分断しない。

既存フィードバックから偏りの懸念を確認したが、具体的な再現入力・同一利用者の武器横断の対応記録・丸め前集計が不足している。個人の記録はローカルのコピーだけで読み、公開・外部送信しない。意識項目名を撃ち方の証拠としない。

## 比較条件と候補

`reward_analysis.gd` は固定乱数の合成条件54件（3武器×6条件×3難度、各120秒）。各武器の低・中・高精度、丁寧な中心狙い、精度を落としたテンポを区別し、HGの10%命中連打、バーストの各標的2発止め、オートの選択射撃を追加した。合成値は人間の代表成績や実際の移動標的への達成可能性を保証しない。難度間で同じ精度を仮定する行は倍率の感度分析であり、難しい方が簡単に稼げるという実測ではない。

HGは毎秒0.65／1／1.7／0.7／2.2クリック、連打だけ毎秒6クリック。バーストも同じクリック頻度で3実発射、弾間85ms（2.2クリック/秒でもバースト間隔は約455ms）。オートは100msの時間積分。丁寧な条件は計測時間の60%、選択射撃は35%だけ発射し、非射撃時間も分母へ含む。部分命中は3標的の各2命中までで行き止まりとなる実装に従い、標的が無限に新生すると仮定しない。

各qを累乗した値を採点前に集計し、平均qや整数内訳から逆算しない。表示P/分は丸め前ポイント÷全計測時間×60。初回増員70P・装備120Pまでの参考時間を同じ価格で算出し、実購入の待ち時間を保証しない。

- 候補A：HG係数だけ0.105→0.100。他武器・条件は不変。
- 候補B：速度＋連続の上限だけ基本の20%→10%。基本・中心・武器係数は不変。
- 両候補は開発用の再評価関数だけに存在し、製品の係数・UI・セーブに適用していない。

## 採用しない理由と限界

HGのテンポ条件は丁寧条件より約23.6%高いが、成功回数も違う。これは許容される速さと精度の交換関係でも説明でき、望まない稼ぎ方を強制しているという定量的証拠にはならない。候補Aは武器内の比率を変えず、候補Bでも約20.8%の差が残る。問題のない通常練習まで減らす一方、目的の改善を確定できないため採用しない。

低～中精度条件への影響は候補でも目安の±10%以内だが、それだけでは採用根拠にならない。別の撃ち方として連打・部分止め・選択射撃・高ペースも両候補で再評価したが、これは有限の合成検査であり、抜け道がないことや人が行動を変えないことを証明しない。

## 次に必要な最小の対応試験

同じ人・同じ難度／FOV／感度で、まず各60～90秒を目安に任意終了する6回を比較する。時間制限モードは追加しない。

1. HG：本人の普段の練習と、精度を落としてテンポを上げた練習。
2. バースト：標的を完了させる練習と、途中で標的を切り替える練習。
3. オート：普段の継続追従と、追いやすい瞬間だけ撃つ練習。

全計測時間当たりの獲得・技能指標・本人の好む撃ち方を照合する。望まない側の過大な優位が出た組だけ順番を逆にして再実施し、疲労・順序・標的の偶然を切り分ける。本人の好みは意識項目ではなく直接確認する。外部送信は不要で、本人の同意なく記録を公開しない。

## 記録と保存

新しい記録には任意の `scoring_raw` v1として基本・中心・速度・連続の採点前集計4値を追加し、セッションID・武器・難度・時間・採点版は既存領域に対応付ける。将来の係数・上限の同じ射撃に対する再評価へ使える。q分布やイベント時刻が必要な変更は、この4値だけでは再評価できず、開発用入力再生が必要。

旧記録を補完・再採点・減算・追加精算しない。既存15秒台帳のスナップショットへ付加するだけで、新しい報酬経路はない。`scoring_capture_schema` の初回読込前に `user://save_before_reward_v1_7.json` を一度だけコピーし、失敗時は原本を保持して保存を停止する。中断記録は保存済みの当時の点をそのまま確定し、再加算しない。全フレームや全入力の永続保存は追加しない。
